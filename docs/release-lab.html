Release Lab evidence

Manual and external gates are closed from reviewed evidence, not from an unchecked status flag. Reeris keeps automated prerequisite evidence separate from evidence that is allowed to close a 1.0 gate.

Closure model

1. Capture

Create evidence for one or more explicit gate criteria.

2. Verify

Artifacts are repository-relative and SHA-256 verified; records must match the release and allowed evidence type.

3. Review

Closing evidence must have a passing outcome and an explicit approved review. Pending or rejected records cannot close anything.

4. Reconcile

npm run evidence:sync derives each gate from its criteria. Every required criterion must pass before the gate changes to passed.

Commands

npm run evidence:templates
npm run audit:evidence
npm run evidence:sync
node tooling/release-lab-evidence.mjs import evidence.json
node tooling/release-lab-evidence.mjs import-browser --latest

audit:evidence never mutates release state. evidence:sync is deliberately separate so gate closure is always an explicit action.

21 closure criteria

The seven release gates are decomposed into 21 independently auditable criteria: four desktop browsers, three real mobile browsers, four assistive-technology checks, three zoom/touch checks, two contrast/high-contrast checks, two visual-baseline checks, and three public-name/namespace clearance checks.

The policy lives in tests/release/gate-criteria.json; the current derived state lives in tests/release/manual-gates.json.

Supplemental evidence is intentionally weaker

Playwright Chromium, Firefox, WebKit, Edge CI, and mobile emulation remain valuable release evidence. The CI workflow normalizes them into Release Lab records, but marks them supplemental. They cannot satisfy criteria such as real Safari, real iOS/Android, NVDA/VoiceOver/TalkBack, real browser zoom, Windows High Contrast, or human-approved visual baselines.

Evidence record contract

Every record has a stable ID, release version, gate, evidence kind, role, collection time, outcome, claimed criteria, test environment, hashed artifacts, notes, and review state. A passing closing record must include at least one verifiable artifact. Name/namespace clearance is marked persistent across versions; ordinary test evidence must target the current release.
