Reeris UI 0.50

Release Candidate readiness

Core is feature-frozen. The RC gate now distinguishes reproducible automated evidence from real-browser, assistive-technology, visual-baseline and public-publication checks that must still be completed outside this build environment.

RC public API freeze

The normalized public Core and optional-JavaScript surface is captured in tests/release/public-api-freeze.json. The snapshot covers public class selectors, public --reeris-* tokens and hooks, Reeris-owned data attributes and their documented values, package exports, optional JavaScript APIs, and published Core source-module names.

732 classes 518 tokens/hooks 11 data attributes 14 package exports 5 JS API entries

During the RC cycle, changing this snapshot requires an intentional review and changelog entry instead of silently drifting the public contract.

Automated RC gate

npm run release:check

The full release command rebuilds Reeris, runs all acceptance audits, verifies deterministic output and package payloads, validates documentation and starters, checks the RC API freeze, and writes release evidence. It does not publish to npm.

Manual gates before 1.0

Passing automation qualifies a source/tarball build for the RC validation cycle, not for final 1.0 conformance. The following evidence remains required:

  • Desktop Chrome, Edge, Firefox and Safari browser matrix.
  • Safari on iOS/iPadOS and Chrome on Android, including native controls and safe areas.
  • Keyboard-only and representative screen-reader testing.
  • Real-browser 200%/400% zoom and reflow plus coarse-pointer/touch checks.
  • Windows forced-colors/high-contrast review.
  • Approved PNG visual-regression baselines in a functioning browser/CI environment.

The machine-readable registry is tests/release/manual-gates.json.

Public publication gate

Before a public registry/repository launch, the final Reeris UI project name, package namespace, repository naming and appropriate trademark/conflict review must be confirmed. That external clearance is deliberately tracked separately from code quality.

Deprecation contract

DEPRECATIONS.md formalizes the lifecycle: Supported → Deprecated → Migration period → Removed in the next major version. There are currently no deprecated APIs.
