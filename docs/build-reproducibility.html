Build reproducibility & source maps

Production artifacts are generated deterministically and can be traced from compiled CSS back to the individual Reeris source modules.

Deterministic build contract

npm run audit:repro performs two clean builds and compares the complete @reeris/core and @reeris/js distribution trees by SHA-256. The file list and every emitted byte must match.

Build artifacts contain no generated timestamps or machine-local absolute paths. Timestamped release reports are intentionally outside the deterministic distribution boundary.

Source maps

Both reeris.css and reeris.min.css publish Source Map v3 files. The maps point to the actual CSS modules copied under dist/sources/, allowing DevTools to identify files such as components/button.css rather than only the compiled bundle.

Clean distribution

The build removes the previous Core distribution before generation, rebuilds tokens from the canonical token source, emits CSS and JS in sorted deterministic order, then publishes only intentional package artifacts. Stale files therefore cannot silently survive from an earlier release.

Release verification

npm run build
npm run audit:repro
npm run release:check

The normal release gate includes reproducibility verification before package dry-run checks and release-manifest generation.
