Theme contract

Themes & token validation

CSS custom properties are Reeris's universal runtime theme format. Themes may be partial, nested, and inherited; no JavaScript theme engine or recompilation is required.

System scheme by default

With no theme attribute, Reeris follows the browser/OS color preference. Use data-theme="light" or data-theme="dark" only when an application deliberately overrides that preference.

Glass style

Set data-theme="glass" on the root element to use translucent semantic surfaces over a soft canvas. It selects the light color scheme for native controls, and falls back to opaque surfaces when reduced transparency is requested. The Core style uses CSS only.

<html lang="en" data-theme="glass">
  <!-- Include Reeris Core CSS and use its regular components. -->
</html>
Glass

Same components, new surface

The theme changes inherited colors and surface treatment without changing component markup.

Partial custom themes

A custom theme overrides only the semantic relationships it needs. Everything else continues through normal CSS inheritance.

[data-theme="ocean"] {
  --reeris-color-primary: oklch(48% .16 235);
  --reeris-color-on-primary: white;
  --reeris-gradient-primary: linear-gradient(135deg,
    oklch(48% .16 235), oklch(45% .13 195));
}

Validation CLI

Validate a custom theme against Reeris's inherited base tokens and WCAG AA semantic color relationships:

node tooling/theme-validator.mjs path/to/theme.css

The release gate validates Reeris's official light/dark semantic pairs, gradient endpoints, the nested custom-theme fixture, and the independence of density/radius/elevation/motion personalities.
