Security, CSP & package release hardening

Release security is treated as an auditable contract rather than a publishing-time checklist.

Strict CSP boundary

Normal Core operation requires no JavaScript. Optional @reeris/js is audited against dynamic-code, unsafe-HTML, storage, network and script/style-injection sinks. A strict-CSP fixture runs with external CSS/JS only and does not request unsafe-inline or unsafe-eval.

The glide enhancement sets constrained CSS custom properties through the CSSOM for measured geometry; it does not generate stylesheet text or insert application HTML.

Package boundary

@reeris/core and @reeris/js publish only their dist/ artifacts plus npm-required metadata, README and MIT license. The private repository src/ tree, reports and internal tooling are excluded from the package payload. Reeris 0.42 intentionally publishes mapped CSS source copies under dist/sources/ for DevTools source-map resolution.

Release gate

npm run release:check

The command rebuilds Reeris, regenerates the API reference, runs every Core acceptance gate including security and package integrity, then writes a SHA-256 release manifest. It deliberately does not publish to npm.

Disclosure policy

The repository root SECURITY.md defines private vulnerability reporting, supported-version policy, coordinated disclosure and security-release handling. CHANGELOG.md records notable release changes.
